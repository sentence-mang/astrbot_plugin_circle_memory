# astrbot_plugin_circle_memory

跨平台共享上下文插件（circle_memory）：将多个平台的多个会话组织为**会话组**，组内所有会话共享同一份对话历史。任何第三方插件均可通过组 ID 直接定位组共享会话，无需适配。

- **兼容性**: AstrBot >= 4.0.0
- **许可证**: MIT

## 1. 功能概述

- 将任意平台（飞书、微信、QQ、Telegram 等）的任意会话（私聊、群聊）加入同一会话组；
- 组内会话共享同一份对话历史：用户在平台 A 的对话，可在平台 B 无缝接续；
- 每个组拥有稳定短 ID（`g-<8位hex>`），组共享会话以**组 ID 作为 conversation_id** 入库；
- 其他插件按 conversation_id 读写会话时直接使用组 ID 即可，**零适配成本**；
- 组管理完全通过 `/shared` 命令完成：创建、邀请码加入、退出、**管理员移除成员（踢人）**、解散、组 ID 查询、成员列表、**成员昵称（alias）**、**组置顶（pin）**、**组摘要（summary）**；
- **退出/被踢数据处理策略**（`exit_data_policy`）：默认会话重置无副本，可选导出成员自己的发言（服务器留档 + 私聊发送）；
- **共享历史增强**：媒体降级（跨平台失效图片防护）、成员身份注入、历史预算折叠与 AI 摘要、图片轮数控制；
- 解散/末人退出时共享历史**自动归档**（保留最近 10 份），防数据丢失。

## 2. 核心概念

| 概念 | 说明 |
|---|---|
| **会话（UMO）** | `unified_msg_origin`，格式 `platform:message_type:session_id`，AstrBot 中标识一个独立聊天会话 |
| **会话组** | 一组会话的集合，每个组有唯一名称与唯一 ID |
| **组 ID** | `g-<8位hex>`（如 `g-15c34813`），全局唯一，稳定不变 |
| **组管理员（创建者）** | 创建组的会话（UMO），拥有解散组、移除成员、设置置顶、生成摘要的权限；创建者退出后自动移交给剩余成员中第一个 |
| **组共享会话** | 数据库中一条 conversation 记录，其 conversation_id 恒等于组 ID |
| **消息流水** | 插件记录的组内成员消息（时间/会话/昵称/文本），用于个人发言导出 |

约束：

- **一个会话只能属于一个组**；加入新组前必须先退出当前组；
- 组名全局唯一（创建时校验），长度 1–32 个可见字符；
- 共享历史为物理合并，不可逆（见「数据生命周期」一节）。

## 3. 工作原理

AstrBot 中每个会话通过 `ConversationManager` 映射到一个 conversation_id。插件在两处介入：

**请求前（`on_waiting_llm_request`，先于对话构建）**：

1. 解析当前 UMO 所属的会话组；
2. 若组共享会话未就位（新组 / 旧版 uuid / 迁移中断），幂等创建以组 ID 为 cid 的会话，并继承来源历史；
3. 将组内所有成员 `switch_conversation` 到组 ID 会话；
4. AstrBot 按 UMO → conversation_id 原生读写历史，组内天然共享。

每次请求仅做常数次映射查询与 O(组内成员数) 的切换检查，无历史数据复制或注入。

**请求构建后（`on_llm_request`，仅共享会话请求触发）**：

- **媒体降级**：历史中的图片按 `media_mode` 处理（占位/移除/LLM 转述），并支持 `image_window` 轮数控制，防止跨平台失效图片拖垮请求；
- **成员标注**：组内成员昵称映射（`/shared alias`）与组置顶（`/shared pin`）以**单次注入**方式写入 system_prompt——每轮重建、不进历史、无累积；
- **预算折叠**：历史超过 `history_budget` 时折叠为「最近消息全量 + 头部 AI 摘要（可选）+ 中段省略标记」。

## 4. 会话组 ID（插件集成契约）

**组共享会话的 conversation_id 恒等于组 ID。** 任何插件只要按 conversation_id 操作会话，直接填组 ID 即命中组共享会话，无需感知本插件存在。

可用于以下路径（AstrBot v4 `ConversationManager` / `Database` API）：

- `cm.get_conversation(umo, group_id)` — 读取会话（v1 格式，`history` 字段）
- `cm.add_message_pair(group_id, user_msg, assistant_msg)` — 追加对话对
- `cm.db.get_conversation_by_id(cid=group_id)` — 读取原始记录
- `cm.db.update_conversation(...)` — 更新记录
- `cm.get_curr_conversation_id(umo)` — 成员当前会话即组 ID

```python
# 示例：向组共享会话追加一条对话（任意插件内）
cm = event.bot_context.conversation_manager
await cm.add_message_pair(
    "g-15c34813",
    {"role": "user", "content": "问题"},
    {"role": "assistant", "content": "回答"},
)
```

组 ID 获取方式（按权限）：

- 组内成员发送 `/shared id` 查询自己所在组的 ID；
- 组内成员发送 `/shared list` 查看自己组的 ID 与成员明细；
- 管理员发送 `/shared id <组名>` 或 `/shared list` 可查询任意组（含组外）；
- 管理员直接查看插件配置 `user_groups[].id`。

组外普通会话无法通过任何命令获取组 ID。

## 5. 安装

1. 将插件目录放入 AstrBot 的 `data/plugins/`；
2. 在 Web 面板插件页启用；
3. 首次激活时，插件自动完成旧版配置迁移（见「版本迁移」一节）。

## 6. 命令参考

所有命令均需向机器人发送；`/` 前缀可省略（取决于唤醒词配置）。`[组名]` 表示可省略（省略时作用于**当前会话所在组**）。

权限角色：**成员** = 会话在组内；**组管理员** = 创建该组的会话（可解散组、移除成员、设置置顶、生成摘要，退出时自动移交）；**平台管理员** = AstrBot 管理员列表中的会话（可组外查询，owner 缺失时可兜底）。

| 命令 | 权限 | 说明 |
|---|---|---|
| `/shared create <组名>` | 任意会话 | 创建组并加入当前会话（创建者即首个成员，也是组管理员） |
| `/shared code [组名]` | 组内成员 | 生成 6 位邀请码（5 分钟有效，失败 5 次作废） |
| `/shared join <组名> <邀请码>` | 任意会话 | 验证通过后加入组 |
| `/shared leave [组名]` | 组内成员 | 退出组；支持序号（`leave 1` 按 list 顺序）与 `leave all`；创建者退出自动移交；最后一名成员退出自动解散并归档历史 |
| `/shared remove [组名] <成员会话ID>` | **组管理员** | 将成员移出组（踢人）；被移除者会话重置、组 ID 立即失效；组管理员本人不可被移除 |
| `/shared dissolve [组名] 确认` | **组管理员**（创建者） | 解散组（需二次确认）：重置所有成员会话、归档后删除共享历史 |
| `/shared id [组名]` | 成员 / 平台管理员 | 查询组 ID：成员查自己所在组；平台管理员可查任意组（含组外）；组外普通会话不可查询 |
| `/shared list` | 任意会话 | 查看组列表：成员见自己组的 ID、成员明细与创建者；平台管理员全量可见；组外普通会话仅见组名（无 ID） |
| `/shared alias [组名] [<成员会话ID> <昵称>]` | 成员（本人）/ 组管理员（任意成员） | 设置/查看/删除成员昵称（`-` 删除）；昵称用于成员标注注入与通知文案 |
| `/shared pin [组名] <内容>` | **组管理员** | 设置/清除组置顶（`-` 清除）；置顶内容每轮注入共享会话请求最前 |
| `/shared summary [组名]` | **组管理员** | 调用 LLM 生成组共享历史摘要（消耗 token，用当前会话 provider） |

## 7. 配置项

配置文件：`data/config/astrbot_plugin_circle_memory_config.json`（`user_groups`、`merged`、`aliases`、`pins` 为内部字段，Web 面板隐藏，由命令维护，请勿手工编辑）。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 总开关；关闭后共享切换与命令均不生效 |
| `exit_data_policy` | string | `discard` | 退出/被踢成员数据处理：`discard`=会话重置无副本；`mine_only`=额外导出该成员自己的发言（服务器留档 + 尽力私聊发送，发送失败明确反馈） |
| `archive_keep` | int | `10` | 解散/末人退出归档保留份数，超过自动清理最旧 |
| `media_mode` | string | `placeholder` | 共享历史图片处理：`ignore`=移除；`placeholder`=替换 `[图片]` 占位；`caption`=调用 LLM 转述（消耗 token） |
| `image_window` | int | `0` | 图片轮数控制：仅保留最近 N 条用户消息中的图片（0=全部按 media_mode 处理），更早的转占位（省 token） |
| `history_budget` | int | `0` | 共享历史字符预算上限（0=不限制）；超限时折叠：最近消息全量 + 头部摘要 + 中段省略 |
| `summary_enabled` | bool | `false` | 折叠时是否调用 LLM 生成历史摘要（消耗 token；关闭时用省略标记） |
| `summary_target_chars` | int | `800` | 历史摘要目标长度（字符） |
| `skip_commands` | bool | `true` | 记录消息流水时跳过 `/` 开头的命令消息（`/shared` 系列始终跳过） |
| `user_groups` | list | `[]` | 组列表，每项 `{name, id, owner, umos[]}`（owner 为创建组的管理员会话，自动维护） |
| `merged` | dict | `{}` | 组名 → 组 ID 映射（迁移状态标记） |
| `aliases` | dict | `{}` | 组内成员昵称映射（`/shared alias` 维护） |
| `pins` | dict | `{}` | 组置顶内容（`/shared pin` 维护） |

## 8. 安全模型

| 威胁 | 缓解措施 |
|---|---|
| 未授权加入组 | 加入需 6 位数字邀请码；仅组内成员可生成；5 分钟有效、一次性使用 |
| 邀请码暴力枚举 | 每个邀请码最多 5 次错误尝试，超限立即作废（须重新生成） |
| 越权解散 / 移除成员 / 设置置顶 / 生成摘要 | 生成邀请码仅组内成员；解散、移除成员、置顶、摘要**仅组管理员（创建者）可操作**，其他成员即使组内也被拒绝（按 owner 校验） |
| 组管理员被移除 | 组管理员本人**不可被移除**（只能移交或解散）；创建者退出时组管理员自动移交给剩余第一成员；owner 异常缺失时平台管理员可兜底解散 |
| **组 ID 泄露（组外查询）** | 组 ID 是组共享会话的授权凭证：组外普通会话的 `list` 仅显示组名，`id` 拒绝查询；仅组内成员可查自己组的 ID，管理员可组外查询任意组 |
| **跨组信息泄露** | 组内成员的 `list` 只显示自己组的成员明细与其他组的组名，其他组的 ID 与成员不可见 |
| 会话越权 | 组外会话看不到任何组的 ID 与会话内容 |
| 被移除/退出后残留 | 退出/被移除即重置会话为独立空对话，组 ID 立即失效；消息流水按组隔离 |
| 个人发言导出泄露他人隐私 | `mine_only` 仅导出**该成员自己的发言**（按会话过滤消息流水），不含他人发言与系统注入；整组历史归档为服务器资产，不发送给退出者 |

注意：本插件不实现身份认证——组 ID 是"可猜测性极低"的授权凭证（32 位熵），但不应对不可信方公开。验证码与组 ID 均在进程内存中管理，AstrBot 重启后验证码失效（需重新生成），组 ID 持久化于配置文件。

## 9. 数据生命周期

- **加入前**：会话历史保留在原会话，不并入共享历史；
- **加入后**：组内全部对话写入组共享会话（物理合并，不区分来源）；消息流水记录组内成员发言（用于个人导出）；
- **退出 / 被移除**：
  - 会话重置为独立空对话，组 ID 访问权立即失效（重新 `join` 可恢复组历史可见，组历史未删除）；
  - 按 `exit_data_policy` 处理：`discard` 无副本；`mine_only` 导出该成员自己的发言 → 服务器 `archive/personal/` 留档 + 尽力私聊发送（发送失败明确反馈"已保存到服务器但私聊发送失败"）；
  - 通知组内剩余成员（主动退出 / 被移除两种文案）；
- **解散 / 最后成员退出**：所有成员重置为独立空对话，组共享历史**归档**（`archive/groups/`，保留 `archive_keep` 份）后物理删除；组管理员无 owner 时平台管理员可兜底解散；
- 被踢与主动退出的数据处理策略一致，被踢不获得额外数据权。

合并是单向、不可逆的：解散后无法将合并历史拆回各成员（归档保留完整快照供审计/恢复）。

## 10. 版本迁移

从 1.0.x（共享会话为随机 uuid）升级到 1.1.0：

- 插件激活时（`initialize()`）与首次 LLM 请求时双重触发迁移；
- 每个组自动获得 `g-<8位hex>` ID；原 uuid 会话内容完整复制至组 ID 会话；
- 所有成员切换至组 ID 会话；旧 uuid 会话物理删除；
- 迁移幂等、可重入：中断后下次加载自动续迁，重复执行不产生重复数据。

从 1.1.x 升级到 1.2.0：配置自动扩展新键（`exit_data_policy` 等），无数据迁移；消息流水自启用起记录（历史消息不补记）。

迁移日志关键字：`[CircleMemory] 组 %s 共享会话已迁移为组 id %s`。

## 12. 已知限制

- 与抢占消息的插件（如 PrivateCompanion 类）可能存在事件优先级冲突，若聊天异常请先排查此类插件；
- 验证码仅存于单进程内存，多进程部署下不共享（AstrBot 默认单进程，无影响）；
- UMO 通配模式使用 `fnmatch` 语义（`*`、`?`、`[]` 为通配符），配置时请注意转义；
- 组名不支持空格以外的分隔符限制，含空格的组名在 join 时通过从右解析验证码支持；
- **reset 语义**：组内成员 `/reset` 会话后，下一次请求会因共享机制自动切回组会话（个人视角重置不生效）；如需清空组历史请由组管理员 `dissolve` 后重建；
- **增量注入保缓存**：真合并历史天然连续，不做"临时注入式"的增量注入；token 控制由 `history_budget` 预算折叠承担；
- `mine_only` 个人发言导出仅覆盖**插件启用后**记录的流水（消息流水自部署起记录，不补记历史消息）；
- 图片转述（`caption`）与摘要功能会消耗 LLM token，默认关闭或按需启用。
